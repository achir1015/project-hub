# Achir1015專案彙整

線上即時彙整 [achir1015](https://github.com/achir1015) 在 GitHub 上的所有專案。
你可以自己安排分類，每個分類是一個資料夾頁簽，點選頁簽就能看到該分類的專案。

---

## 一、快速開始

| 使用方式 | 怎麼開啟 |
|---|---|
| **單一檔案版** | 下載 `Achir1015專案彙整.html`，用 Chrome 或 Edge 直接雙擊開啟 |
| **線上版** | 打開 GitHub Pages 網址（例如 `https://achir1015.github.io/project-hub/`） |

打開後按右上角 **「🔄 彙整 GitHub」**，就會抓取你所有專案的最新資料。

## 三、功能與操作

### 1. 🔄 彙整 GitHub

每按一次，就向 GitHub 即時抓取：

| 項目 | 來源 |
|---|---|
| 專案名稱、網址（可點選開啟） | GitHub 儲存庫資料 |
| 被點星星的次數 ★ | GitHub 儲存庫資料 |
| 說明 README | 專案的 README.md（會轉成排版好的內容，圖片也會顯示） |
| 下載版本網址 | 最新的 Release 與附加檔案（APK、EXE、DMG…） |
| 上架 Apple 訊息 | 從 README 自動找出 `apps.apple.com` 連結 |
| 上架 Play 商店訊息 | 從 README 自動找出 `play.google.com` 連結 |
| 視訊位置 / YouTube | 從 README 自動找出 YouTube、影片檔或 GitHub 影片附件 |
| 線上網址 | 儲存庫設定的 Website（例如 GitHub Pages） |

> 連不上 GitHub 時，會自動改用檔案內建的「📦 內建快照」，畫面左上角會標示快照時間。

### 2. 🗂️ 分類管理（新增 / 修改 / 刪除）

按 **「🗂️ 管理分類」** 或頁簽列最後的 **「＋ 分類」**：

- **新增**：輸入名稱後按「＋ 新增」或 Enter，上方立刻多一個頁簽
- **改名**：直接修改名稱欄位
- **換顏色**：點左邊的色塊
- **調整順序**：用 ◀ ▶ 移動頁簽位置
- **刪除**：按 🗑，專案**不會**被刪除，只會回到「未分類」

### 3. 把專案放進分類

1. 點選一張專案卡片（被選中的卡片會有藍框）
2. 在右邊詳細面板上方，點選分類按鈕，變成綠色 ✓ 就是已放入
3. 再點一次就會移出
4. 一個專案可以同時放在好幾個分類

### 4. 資料夾頁簽

- 每個分類一個頁簽，**選中的頁簽是白底紅字**，其他是藍底
- 頁簽上的數字是該分類的專案數
- 「📚 全部」顯示所有專案；「📥 未分類」顯示還沒分類的專案，方便整理
- 專案多時，在框內上下捲動

### 5. 專案卡片

卡片上的小圖示亮起來代表有該項資料：

| 圖示 | 意思 |
|---|---|
| 🍎 | 有 Apple App Store 連結 |
| ▶ | 有 Google Play 連結 |
| 🎬 | 有影片 / YouTube |
| ⬇ | 有下載版本 |
| 🌐 | 有線上版網址 |

看過的卡片右上角會有小灰點。

### 6. 詳細面板（右邊）

| 分頁 | 內容 |
|---|---|
| 總覽 | 所有重點資訊與自己的備註 |
| README | 專案說明全文 |
| 下載版本 | 最新 Release、附加檔案、下載次數；可按「↻ 重新查詢」 |
| Apple | App Store 連結與上架訊息 |
| Play 商店 | Google Play 連結與上架訊息 |
| 影片 | YouTube 直接在面板內播放 |

分頁名稱旁的綠點代表有資料。

**手動補充**：自動偵測不到或不正確時，可以在 Apple / Play 商店 / 影片 / 下載版本分頁中手動填網址，也可以填「上架訊息」（例如：審核中、1.2.0 版已上架）。手動資料優先使用，總覽會標示「手動」。停止輸入半秒後自動儲存。

### 7. 搜尋、排序、篩選

- **搜尋**：專案名稱、說明、程式語言、備註都能搜尋
- **排序**：最近更新 / 星星數 / 名稱
- **篩選**：點 🍎Apple、▶Play 等按鈕，只顯示有該資料的專案（可多選）

### 8. ⚙️ 設定

- **GitHub 帳號**：填帳號名稱 `achir1015`（不是 email）
- **GitHub Token（選填）**：
  - 沒有 Token 時，GitHub 每小時只允許 60 次查詢；專案多時，部分「下載版本」要等下一次彙整才會補齊
  - 填入 Token 可提高到每小時 5000 次，也能看到私人專案
  - 建立方式：GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → 權限選 **Contents: Read-only**
  - Token 只存在你這台電腦的瀏覽器裡
- **顯示 Fork 來的專案**：可勾選是否顯示

### 9. 匯出 / 匯入備份

分類和手動資料存在**這台電腦的這個瀏覽器**裡。換電腦或換瀏覽器時：

1. 舊電腦：設定 → **⬇ 匯出備份**，得到一個 `.json` 檔
2. 新電腦：設定 → **⬆ 匯入備份**，選那個 `.json` 檔

## 四、部署到 GitHub Pages

1. 把這個儲存庫的檔案放到 `main` 分支
2. 到儲存庫 **Settings → Pages**
3. Source 選 **Deploy from a branch**，Branch 選 **main**、資料夾選 **/ (root)**，按 Save
4. 約 1 分鐘後，網址會是 `https://achir1015.github.io/project-hub/`

## 五、程式結構（領域模型）

```
index.html            主頁面
css/style.css         樣式（含深色模式）
data/snapshot.json    內建快照（連不上 GitHub 時使用）
js/
├─ domain/            領域層：只有商業規則，不碰畫面與網路
│  ├─ Project.js        專案（履歷表）、Release、ProjectNote（便利貼）
│  ├─ CategoryBook.js   分類簿（文件夾目錄）
│  └─ LinkExtractor.js  連結偵測器（把網址分抽屜）
├─ infra/             基礎設施：和外界溝通
│  ├─ GithubGateway.js  GitHub API（ETag 快取、次數計算）
│  └─ LocalStore.js     瀏覽器 localStorage
├─ app/
│  └─ ProjectHub.js     應用服務（總編輯）：彙整流程、分類操作
├─ ui/                畫面
│  ├─ Views.js          頁簽、卡片、詳細面板
│  ├─ Readme.js         Markdown → 安全 HTML
│  └─ dom.js            小工具
└─ main.js            進入點（櫃台）：接收點擊、呼叫總編輯、重畫
```

比喻：
- **Project（履歷表）**：GitHub 上的客觀紀錄；**ProjectNote（便利貼）**：你手動補充的資料，顯示時便利貼優先
- **CategoryBook（文件夾目錄）**：刪除資料夾時，裡面的專案不會消失，只會回到未分類
- **GithubGateway（跑腿小弟）**：記住每個網址的版本號（ETag），資料沒變時不佔查詢次數
- **ProjectHub（總編輯）**：指揮跑腿小弟、整理資料、通知畫面更新

## 六、常見問題

**Q：按彙整出現「彙整失敗：Failed to fetch」？**
A：網路連不上 GitHub。確認網路後再按一次；期間會先顯示內建快照。

**Q：出現「API 次數不足」？**
A：沒有 Token 時每小時只有 60 次。等一小時後再按，或到設定填入 Token。

**Q：Apple / Play 沒有偵測到？**
A：README 裡沒有商店連結時偵測不到，請在詳細面板的 Apple / Play 商店分頁手動填入。

**Q：換了電腦，分類不見了？**
A：分類存在原本電腦的瀏覽器裡，請用「匯出 / 匯入備份」搬過去。
